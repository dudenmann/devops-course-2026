# SVN vs Git

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто **указатель на коммит** (ссылка из 41 байта: SHA-1 хеш + имя).
Создание ветки не копирует файлы, а лишь записывает новую ссылку. Операция мгновенная
и не требует места. Переключение между ветками — тоже мгновенное, потому что рабочая
директория обновляется из объектов, уже лежащих в локальном репозитории.

В SVN ветка — это **физическая копия директории** внутри репозитория (через `svn copy`).
SVN хранит историю как последовательность изменений путей, поэтому создание ветки
означает копирование структуры каталогов на сервере. Это медленно и затратно по месту.
Кроме того, для создания ветки нужен доступ к серверу.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — **централизованная** система контроля версий: вся история и все операции
коммита происходят на сервере. Локально можно лишь изменить файлы в рабочей копии
(working copy), но чтобы зафиксировать изменения (создать ревизию), нужен доступ
к серверу.

В Git коммит создаётся локально — в вашей копии репозитория есть вся история, поэтому
интернет не нужен. Отправить изменения на сервер (`git push`) можно позже, когда
появится сеть.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Legacy-проекты в госсекторе и банках**, где SVN уже развёрнут и переход дорог.
- **Жёсткий контроль доступа**: в SVN права можно задавать на отдельные директории,
  в Git — только на репозиторий целиком.
- **Большие бинарные файлы** в больших объёмах: SVN хранит их по путям и не раздувает
  историю так, как Git (хотя Git LFS решает эту проблему).
- **Централизованное управление** с единой точкой истины — удобно в организациях
  с бюрократическими процессами и строгим аудитом.
- **Простые линейные истории** без сложного ветвления — SVN справляется без излишней
  сложности Git.
